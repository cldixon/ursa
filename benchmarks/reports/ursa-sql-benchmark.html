The full graph, step by step

All 2,416,311,437 follows with all 39,650,447 users as nodes, on one EC2 r7g.4xlarge (16 vCPU, 128 GiB), ursa 0.10.0, each step in its own process. 70 minutes of instance time, about $1.10. Memory isn't the limit any more; time is. Triangles uses all 16 cores but grows with the hubs; Louvain and the components stay near one core; and every query pays a 15 s index load.

How to read this

  • One run per platform. These are a baseline, not a leaderboard. Fargate's hardware generation isn't selectable, so its times vary between runs; repeat before quoting a ratio.
  • Memory differs by platform. The laptop numbers are macOS peak footprint. EC2 and Fargate peaks are Linux ru_maxrss; the platform table lists EC2's, and Fargate's match within 0.01 GB.
  • Two releases on this page. The release, platform and profile sections are ursa 0.9.0; the full-graph sections are 0.10.0, which made builds 3–6.5× faster and Louvain's peak about half. The round-4 report has the 0.10.0 laptop numbers.
  • The full graph ran once, on one EC2 r7g.4xlarge. Its memory figures are Linux ru_maxrss; its times include the 15 s index load each new process pays.
  • 0.6.0 is left out. It counted only the endpoints of edges as nodes, so its numbers measure a different graph.
  • The companion report is the July flywheel, Ursa's Python API against NetworkX, rustworkx and igraph. A SQL version, with DuckDB + DuckPGQ, is the next step in benchmarks/SQL_PERFORMANCE.md.
